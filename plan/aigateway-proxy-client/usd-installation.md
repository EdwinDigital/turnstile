## 必要安装顺序

| 顺序 | 必要动作 | 完成标准 |
| --- | --- | --- |
| 1 | 核对现有备份、运行包、配置、APIM 策略及数据库/账本 | 有可用的恢复材料；明确正在维护的资源和已完成阶段，不覆盖已有 journal |
| 2 | 补齐匹配的 API、Telemetry、Control-plane、Observer 及其网络/身份权限 | 实际 worker 使用正确版本，各自身份可以访问同一现有账本；Observer 可记录完成证据 |
| 3 | 安装兼容 Token/USD 的 APIM 策略、模型价格和计数契约 | 保留订阅鉴权、用户身份、模型权限及 TPM；全部可达旧修订没有准入旁路 |
| 4 | 在真实暂停与排空后初始化执行状态和期初 | 新鲜 SQL/旧账本一致；旧消费不归零；通过正常 scope 服务建立策略和价格投影 |
| 5 | 完成候选发布接管和真实就绪验证 | APIM 实际修订与 SQL 发布记录一致；身份及执行验证证据有效；不绕过 USD 保存保护 |
| 6 | 通过正常平台 API 配置目标预算 | 同一月份组织 `usd_limit="100.00"`、部门 `usd_limit="70.00"`；保留其他组织和个人预算 |
| 7 | 执行最小真实验收 | 一次有界 USD 请求的预留、用量、正式事件和金额结算对齐；已有 Token 路径成功，未知结果不重放 |
| 8 | 完成激活、恢复发布和普通请求 | 解除已验证维护暂停，读回最终预算和业务状态；清理临时访问，数据库保持运行 |

准备、隔离验证与正常流量激活是不同阶段。具体的 paused 验证窗口和首次准入顺序遵循安装器保护，
不能为了保存金额或发测试请求而提前开放普通流量。扩展并发、流式和异常矩阵不冒充核心路径完成，
也不以追加无关工具延迟核心交付。

## 配置不是只开三个开关

- 执行读取及目标：`BUDGET_EXECUTION_ENABLED`、`BUDGET_EXECUTION_TARGET_IDS`。
- 服务间可信委托：`BUDGET_DELEGATION_TARGETS`、`BUDGET_DELEGATION_TRUST`。
- 完成证据：Observer 的 `BUDGET_COMPLETION_ENABLED`，以及其真实镜像、网络和账本权限。
- 金额结算：Telemetry 的 `BUDGET_SETTLEMENT_ENABLED` 及正常事件/恢复处理。
- 预留核销：`BUDGET_RESERVATION_RESOLUTION_ENABLED` 是单独受控能力，不是开启 USD 下拉框的捷径。
- `CONTROL_PLANE_ENABLED` 等普通发布开关不代表金额准入已安装。各服务按职责配置，不把所有开关无区别设为 true。

## 测试范围与恢复边界

测试组织中已有普通用户、无预算、无模型权限、组织/部门/团队管理员及禁用账号场景。
已保留的测试证明涵盖密码登录、目录范围、下载门槛和拒绝行为；这些不是 USD 扣费证明。
`qa-usd-standard`、`qa-usd-no-model` 是配套测试订阅；原测试记录为 Token 应用额度，
不可因名称含 USD 就当作金额预算。账号及口令不放入此文档。

后续不改绑平台 Dashboard 默认订阅，不擅自分配个人金额，不修改客户端/WorkBuddy 配置。
软件包回退与金融激活后回退分开：后者必须暂停、排空、核对最新消费，不能恢复旧余额，
也不能简单关闭开关或切回旧 APIM 修订。备份位置见[恢复索引](release-history.md#恢复材料)。
