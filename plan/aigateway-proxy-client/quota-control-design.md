# 用户版 0.4.2：magpie 本地额度控制

## 规则与边界

有效本地阻断 = 平台强制阻断 OR 用户明确开启本地阻断。

| 平台模式 | 本地选择 | 插件返回的 aside | 原生历史 |
| --- | --- | --- | --- |
| audit | 默认关闭 / 用户关闭 | true | 不新增采样 |
| audit | 用户开启 | false | 宿主自动采样并绘图 |
| block | 不可修改 | false | 宿主自动采样并绘图 |

只改变用户版 auth.usage 向 magpie 返回的个人窗口副本。不改变平台 mode、Token 数、
月度周期、用户身份、默认订阅、模型权限、APIM、Core、数据库结构或历史原始记录。
订阅版仍为 0.1.2；不修改 magpie 源码，不手工注入宿主 quota-history.json。

平台强制阻断不能被本地配置关闭，包括本地文件被篡改或损坏的情况。
无个人预算不创建窗口，不制造额度；未知/歧义的个人窗口拒绝配置。
本地只是提前拦截，跨客户端并发、最终预算判定和真实计量仍由平台执行。

实际原生验证发现：只有 aside=false 并不保证指定单个模型的请求被宿主拒绝。因此文本
loader 还执行调用前额度检查，超额返回本地 429 且不发送模型请求；不把绘图能力当作阻断证明。
图片/MCP 配套助手在本地选项开启时也执行检查，模型调用依旧只使用 image-only capability。
助手从本机既有授权槽读取当前 access，只用于平台只读 usage 查询；不保存或轮换 refresh，
不使用普通 OAuth 凭据调用图片模型。助手版本升级到 3，使旧后台助手被已有替换逻辑重启。

## 配置入口

- 新增用户版 OAuth 方法“额度控制”，不是重新登录；返回已有授权和稳定 uid。
- 使用宿主已有 ask/select 能力；同时声明 prompts，确保 host 将选择输入传给 authorize。
- audit 时显示当前本地状态与开启/关闭选择；未确认/取消不落盘。
- block 时 ask 返回 null，不出现可修改选择；只显示平台强制开启的说明。
- authorize 与最终 callback 均重新查询平台；选择期间管理员启用 block 后，关闭请求拒绝。
- 选项只写 `<magpie config>/aigateway-proxy-user/<providerId>/quota-control.json`，
  含 schema version、稳定内部 userId 和 enabled，原子 0600 写入。跨用户、损坏文件拒绝覆盖。
- 平台 block 覆盖本地旧的 disabled 偏好，不把强制模式写成用户偏好；未来平台回到 audit
  时，仍使用用户之前的明确选择，不自动替用户开启。

## 刷新与历史

- `GET /api/v1/client-runtime/usage?fresh=true` 只在显式配置问答/确认时使用；依旧要求
  当前用户客户端 Bearer 鉴权，读取个人预算，无配置写入。
- 普通 usage 保持原有 60 秒缓存，不增加后台轮询或强制全局刷新频率。
- 调用前只读额度在插件进程内按平台 as_of 缓存至多 60 秒，同 access 的并发读取合并。
  不增加后台定时器，旧读数不能覆盖刚完成的新策略读数；读取失败不能当作不限额。
- 新鲜读取同时更新本 grant 的缓存，减少配置成功后继续展示旧模式的时间。
- 原生走势图由 magpie 自己记录；开启后从真实采样开始，不补安装前历史。
  用户需将宿主“走势”设置保持为非关闭。关闭本地阻断后，停止新增原生采样，
  但宿主保留的旧历史可能仍显示，插件不删除或伪造它。
- 独立“查看额度趋势”页继续记录平台原始窗口，标注“平台仅记录，不阻断”，
  不把用户选择的本地阻断误描述成平台强制策略。

## 验证范围

- JS：默认关闭、显式开关、强制锁定、篡改/损坏配置、取消不写、保存前策略变化、
  无预算/无效窗口、私有权限、原始窗口不变、授权及其他账号不变。
- API：普通缓存保留；fresh 越过旧 audit 读取新 block 并更新缓存；fresh 仍需鉴权。
- 原生：用隔离 HOME/XDG、模拟平台与实际插件登录方法验证选项传递、原生历史采样及阻断。
  不通过修改线上用户预算来测试超额行为，不触碰日常 Agent 配置。
- 发布：只部署既有 API 包，记录原包/配置、19 项迁移校验和与 Core 摘要；验证挂载包、
  实际下载 ZIP、默认订阅、价格和一次获准的小调用。保留 Functions/APIM/生产设置。
