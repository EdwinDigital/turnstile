本记录区分软件发布与金融准入激活；后者不能通过部署应用包或修改开关自动完成。

| 范围 | 本次实现 | 兼容边界 |
| --- | --- | --- |

| 原生代理 | 应用生命周期 HTTP 连接池，逐请求身份与凭据，拒收上游 Cookie | 不引入结构化调用 DTO，不改原生 SSE、工具和请求正文协议 |

| 会话追踪 | 单独白名单转发 Agent、会话和轮次；个人/组织/订阅由服务器写入 | 客户端报告的追踪信息不是鉴权依据 |

| USD 模型目录 | 按当前个人预算单位和策略版本刷新，仅允许匹配模型身份、已验证协议及有效价格 | 未验证估算仍可用于旧 Token 路径，不能作为 USD 金额上界 |
| 预算能力 API | 已认证、no-store 的 capabilities 及预算编辑器就绪提示 | 检查当前周期、目标、委托、发布、epoch、计数契约；不在打开表单时扫描 ARM |
| 周期初始化 | 数据库目录模式发现当前有效人员，不再依赖静态示例人员列表 | 不新增账号、预算或用量；沿用已有 scope 初始化与个人治理标识 |
| 旧策略接管 | 补齐 schema-one 模板，严格验证旧客户端扩展后离线规划 schema-two 父策略 | 未知策略、错误网关、已有 epoch、未证明的目录扩展均拒绝；工具不执行云写入 |
| 金额预留 | 拒绝 legacy estimate；整体请求上界传入金额计算，Chat 多采样计入上界 | 不改供应商输出参数；缺少已验证上界时在供应商调用前拒绝 |

## 迁移与初始化

- 无新增 SQL 迁移；没有修改已应用的 40 个迁移文件。
- 新增 Python 代码复用已有目录、scope、rollout、价格、S/A/D 及结算结构。
- 启动仍遵循 migrate、bootstrap、API 顺序；发布本身不创建 active rollout、不 seed 余额。
- schema-one 模板随 API/Control-plane 打包；旧实例缺失模板的发布兼容问题得到修复。
- `scripts/budget_execution_upgrade.py` 是离线规划器，不是已完成的生产安装/回退执行器。

## 金融切换与回退门槛

应用包验证成功不等于 USD 已激活。执行安装前仍须完成设计中的 Observer、所有可达修订共享
fence、精确 ETag、停流排空、fresh readback、价格/计数证据、期初只初始化一次以及真实 Token/USD
结算验收。不能用离线生成成功或页面 capabilities 代替这些证据。

若尚未启用金融协议，回退使用已验证的旧运行包及完整设置，保留当前数据库和账本。
若金融协议已经产生新消费，必须先 paused、排空和结算、对齐 SQL/S 摘要、隔离 USD 身份，
再投影最新旧 C/Q 并恢复旧准入；不得恢复旧余额覆盖新消费，不删除 S/A/D 或历史原始数据。
未满足这些条件时应保持受控停止状态，而不是盲目切回旧策略。

生产应用包发布和金融激活结果须在本记录补充实际验收后单独记录。
