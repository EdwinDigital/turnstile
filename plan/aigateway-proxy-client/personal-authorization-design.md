# 用户版默认订阅修复设计（0.4.0，纠正方案）

## 1. 平台设计边界

用户要求修正真正的用户默认订阅，而不是绕过订阅。此前 91a6880 的无订阅/APIM v2 方案仅提交过、本地验证过，没有发布；该方案撤销。APIM 策略、原员工和订阅鉴权、限流、应用账本及模型路由均保持现状。

只读核查确认当前调用测试链路使用默认 Azure API Management 网关；数据库网关没有单独凭据，服务使用 `APIM_DASHBOARD_SUBSCRIPTION_KEY` 回退。通过私密的常量时间 Key 比对，实际对应 `turnstile-dashboard` / Turnstile Dashboard 的 primary Key，不是 cc-switch。

平台没有单独的个人默认订阅字段。个人预算与模型权限按治理用户标识管理；调用测试使用平台订阅 Key，并携带平台验证后的用户归因。用户版应遵循同样的默认凭据配置，不能因为某个应用属于 Edwin、名字靠前或模型较多而选择它。

## 2. 默认订阅解析

- 优先保留已存在、经过访问验证的显式用户默认绑定。
- 未配置显式绑定时，读取调用测试实际默认模型/连接的 APIM 网关路由（不凭应用名称或网关显示名推断）。复用调用测试的凭据优先级：网关配置凭据优先，缺失时才使用 `APIM_DASHBOARD_SUBSCRIPTION_KEY`。
- 服务端将该实际凭据与有效、非系统管理的 APIM 应用订阅主/备用 Key 比对，必须唯一匹配。匹配结果是配置事实，不是按名称推断；支持其他部署的订阅名称及备用 Key。
- 匹配结果缓存 300 秒；缓存键使用平台密钥派生的 HMAC 指纹，凭据变化会失效。不向插件返回 Key，不把指纹写到授权文件。
- 用户版允许使用经上述证明的平台默认订阅，即便它不是用户拥有的应用；个人模型策略、角色、目录身份和现有应用模型策略仍执行。V1 订阅版继续禁止导出平台 Dashboard/master/probe Key，不改变其保护规则。
- 找不到、状态无效或多个订阅匹配时明确失败，不回退到 cc-switch、master 或其他名字靠前的应用。
- 新下载绑定实际默认订阅；现有用户授权保留当前绑定，需「重新登录」更新默认订阅。「刷新模型」只刷新已绑定订阅下本人授权模型。

## 3. 请求、名称与额度

grant.selection 保留 application_id、subscription_id、gateway_id。平台代理保留 Ocp-Apim-Subscription-Key 及现有 v1 签名上下文；上下文继续绑定用户、应用、订阅、model 和 request_id。默认订阅请求复用平台实际配置的 Key，其他已授权绑定保留既有服务端密钥读取方式。绝不进行无订阅请求，也不修改 APIM。

用户名来自验证后的平台 profile；accountId 按宿主约定显示名称，稳定 UUID 保留在 uid。辅助模块只在宿主锁保护下更新本插件自身、同 uid 的已有槽位，避免重登录/改名新增账号，不改 magpie 源码、不影响其他账号，不恢复已退出账号。

额度卡片只返回个人月度 Token；平台及 APIM 的应用统计/限制仍按现有架构执行。个人窗口缓存 60 秒，audit/block 模式不变。不能将「隐藏应用额度」描述为「取消应用预算」或「不计入平台订阅」。

## 4. 预算统计一致性

已确认线上个人总额 22,555，人员列表 19,976。之前将全部 2,579 差值归因于无明细精确结算不充分：生产只读 SQL 已完整分解：19,976 属于 AI Platform，1,847 为 unattributed 部门、240 为 protocol-validation，另外 492 是无明细精确结算；总计 22,555。

修复涵盖两条读取路径：

1. 无明细但精确结算的请求按当月个人/部门预算父级读取投影，不能固定作为 unattributed 在部门筛选时漏掉。
2. 人员列表先读取整月个人用量，再按预算分配的部门筛选人员；个人月度额度不应只统计请求头恰好属于该部门的调用。沿用数据访问范围检查，不返回其他部门的人员。

原始 token_usage、预算、结算和迁移均不改写；组织/部门原始调用归因不为对齐数字而重写。个人配额检查、个人设置和人员列表应遵循同一个整月人员范围。

## 5. 验证与发布要求

先验证默认 Key 主/备用、配置优先级、未知/歧义失败、Owner/Member、目录及模型权限撤销、旧授权保留与重新登录。测试须证明实际请求保留正确订阅 Key 和 v1 签名 application/subscription，伪造 user 被覆盖，用户名仍不重复。

APIM 策略源码恢复为此前版本；上线前后比对实际线上策略及 API 属性，不创建新 revision、Named Value 或发布策略。0.4.0 的所有验收数字以纠正后测试记录为准，不沿用已撤销方案的无订阅代理测试作为新方案证据。

预算统计变更与订阅 Key 比对方法涉及共享 Core，发布仍需协调 API/遥测/控制平面包及运行时摘要，保留完整包、设置与数据库备份。真实调用须确认个人身份和预算正确、默认为实际平台订阅，cc-switch 不因这些调用增加；平台 Dashboard 汇总按既有设计增加是正常的。只撤销独立测试授权，不改日常 Agent。
