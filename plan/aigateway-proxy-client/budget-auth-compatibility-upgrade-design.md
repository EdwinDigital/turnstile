设计基线：2026-10-16，时区 Asia/Shanghai。本文保留已批准的完整方案，不作为实时安装记录。
第 2 节的环境观察、第 12/17 节的阶段清单及“拟议”实现均属于当时的设计上下文；
后续唯一进度入口为 [USD 安装与配置](usd-installation.md)，不能按旧快照重复安装或恢复设置。

本文件汇总本轮源码分析、线上只读预检、备份和隔离验证，作为后续实现、评审、验收与切换的依据。
最初设计阶段未修改应用、数据库或 APIM。后续实现和验收边界见
[实施记录](budget-auth-compatibility-upgrade-implementation.md)，不能将设计清单视为已上线能力。

## 1. 基线、目标与范围

### 1.1 比较基线

- 用户仓库为 `EdwinDigital/turnstile`，不是上游仓库。
- 已核对的远端 `main`：`05bd3e02a20a959a39b54b64b70706c0eac8257a`。
- 本分支设计起点：`codex/aigateway-proxy-client`，提交 `8de47431187f4c29aff0b022a2e0949084080571`。
- 最近已验收运行源码为 `eda02ba`；`8de4743` 是发布记录，不代表再次部署。
- 线上数据是 2026-10-16 当次观察，不是以后执行时可以免查的事实。每次切换必须重新核对。

### 1.2 目标

1. 沿用 main 的统一身份、组织目录、受信后端委托和原子预算执行设计。
2. 继续支持自定义组织、平台密码用户；Entra SSO、目录同步分别可选，不强制迁移用户管理。
3. 同一 APIM/平台 API 下，不同组织可以分别使用 Token 或 USD；原 Token 组织预算、历史和权限不变。
4. 用户版插件保留个人授权、真实默认订阅、原生模型协议和流式转发，不暴露 APIM Key。
5. 补齐 USD 个人额度、原生卡片、趋势、本地额度开关和错误提示，不修改客户端宿主源码。
6. 形成可复现的只读预检、已有安装初始化、候选验证、受控激活及分阶段回退流程。

### 1.3 不可破坏的约束

- 不绕过订阅、身份验证、模型权限、TPM、个人或适用的应用预算；隐藏应用额度不等于取消应用管控。
- 不按应用名称或排序选择默认订阅，不回退到 cc-switch、master、probe 或任意第一个订阅。
- 不把本地密码用户伪装成真实 Entra 用户，不因启用 USD 要求其注册微软账号。
- 不修改已应用的迁移，不清空用量、不重置已用余额、不重新归因历史请求，不自动创建测试业务数据。
- 不修改 Magpie 源码、其他供应商或用户现有 Agent 配置；界面措辞沿用“客户端”。
- 不把开关打开、SQL 执行成功、资源 Running 或健康端点 200 当成金额管控验收。
- 任何 APIM 变更之前先完成新备份和校验；不能用过时备份覆盖最新账本来回退余额。
- 不自动轮换既有秘密、扩大运行时 Publisher 权限或修改数据库定时停机策略。

旧版默认订阅修复中“不修改 APIM”约束针对当时的订阅修复；有效规则已合并到
[插件设计](design.md#默认订阅与身份)。
本方案的 APIM 升级是后来单独要求的金额预算协议安装，不撤销原默认订阅选择与密钥保护规则。

## 3. 身份模型：三个独立维度

| 维度 | 可选方式 | 权威来源 |
| --- | --- | --- |
| 用户登录 | 平台密码、Entra SSO | 既有认证服务、账号状态、会话或客户端 grant |
| 组织人员管理 | 平台维护、单独启用的 Entra/Graph 同步 | PostgreSQL 目录、人员和账号绑定、成员关系 |
| 服务器间信任 | 本轮目标采用 main 的 Entra 受信后端委托 | 经审核的服务身份、tenant/audience/client/object 白名单及目标地址 |

复用 `SessionIdentity.method`、`governance_user_id`、`effective_user_id` 和现有目录权限版本。
不新建“密码组织”和“SSO 组织”两套目录。SSO 成功不自动代表目录已同步、人员已绑定或模型已授权。
账号绑定沿用显式且可审计的机制，不因显示名或未核实的邮箱相同自动合并两个主体。
保留当前治理标识，不为了统一身份把历史邮件标识直接替换成新 UUID。

平台使用托管身份取委托令牌，不要求最终用户存在于该 Entra 租户。
若未来要求完全无 Entra 的服务器间信任，应另行设计验证适配器；不在本次悄悄新增 HMAC 委托协议。
既有 Token 安装在未启用新协议时继续工作，不能因未配置委托而被迫迁移登录方式。

## 4. 当前链路与目标架构

### 4.1 当前用户版

```text
插件个人 access/refresh token
  -> 平台验证 grant、账号、目录人员、订阅、模型和已发布路由
  -> 平台取得真实绑定订阅 Key
  -> 平台签发有效 60 秒的 HS256 客户端上下文
  -> APIM 验证订阅及上下文的签名、issuer、audience、有效期
  -> 核对 model、subscription、request ID，再执行旧 Token 额度逻辑
```

客户端上下文由平台签发，不由 Agent 提供；平台覆盖模型请求中的用户归因。
`employeeToken` 在此分支装的是平台 JWT，`tid/oid` 也不是实际 Entra 租户/对象标识。
旧实现复制员工检查分支，并额外设置 `hasEmployeeToken=true`，属于兼容桥而不是单独的目录体系。

### 4.2 目标用户版

```text
密码 / Entra SSO -> 原客户端 grant -> 统一平台身份及目录权限
                                      |
                       订阅、模型、协议、目标地址检查
                                      |
                  原生请求适配器 + main 的受信后端委托
                                      |
        订阅 Key + 服务身份令牌 + 平台生成的个人归因 + request ID
                                      |
       APIM 验证可信入口 -> schema-two -> 按 scope 的 Token/USD 预留
                                      |
                 原生模型接口 / SSE -> 用量证据 -> 结算与核销
```

主决策：保留插件登录和原生转发，服务器侧优先复用 main 的后端委托，不另建预算引擎。
不把整个 `ModelRuntimeService.invoke()` 作为插件代理替代品。该结构化调用入口的协议范围和
响应模型与透明代理不同，当前还明确拒绝流式工具调用；直接替换会破坏客户端兼容。

### 4.3 共享组件与安全边界

- 从现有运行时中提取/复用受信目标校验、rollout 检查和委托令牌取得，供控制台与客户端代理共同调用。
- 委托组件只接受内部已验证身份和解析后的路由，不接受调用方直接传入“可信 user_id”或任意 URL。
- `selected()`、`validate_model()`、当前账号/grant 和目录人员状态检查保留，Owner 也不豁免财务计量。
- 模型可见范围沿用角色、个人模型策略、应用模型策略、已发布模型及现有 assignment 规则的组合。
- 继续使用有效订阅 Key；真实默认订阅从当前路由凭据唯一匹配，服务器持有密钥，插件不可取得。
- 已安装授权保留绑定；“刷新模型”刷新当前绑定，“重新登录”按既有规则更新授权及默认绑定。
- `x-user-*`、组织、部门、request ID 和委托头由平台最终写入；清除或覆盖 Agent 提供的同名信息。
- 普通 OpenAI `user` 与 Anthropic `metadata.user_id` 继续按现有兼容逻辑赋值，APIM 可信身份不依赖它们。
- APIM 仅接受满足 tenant、audience、client ID、object ID 白名单的后端令牌；验证实际 HTTPS 目标来源。
- 旧上下文与新委托同时出现且含义冲突时拒绝，不以任意一个覆盖另一个；内部凭据不得透传给模型供应商。

### 4.4 旧客户端与其他调用方

| 调用方 | 兼容策略 |
| --- | --- |
| 已安装用户版 | 平台个人授权和模型 URL 不变；上游委托由服务器切换，不强迫全员重新登录 |
| 新版用户版 | 增加 USD 额度契约与能力协商，保持已有账号内部标识和目录名/图标规则 |
| 旧版用户插件遇到 USD | 不能返回 500 或假 Token；提供明确升级状态。能否兼容原生卡片须实测，USD 本地控制要求新版验收 |
| 订阅版 | 保留订阅 Key 直达 APIM 的行为，不自动赋予个人身份；应用预算规则按 main 执行 |
| 原员工 Entra 入口 | 保留原信任与启用状态，不因金额升级自动开启原本关闭的员工入口 |
| 控制台调用测试 | 复用同一委托组件和财务协议，但保留其自身结构化 API 契约 |

旧签名上下文只作为明确版本的过渡入口处理。不得同时运行两套个人预算写入逻辑。
在候选修订中验证新服务器链路，再按切换清单退役或封锁旧入口；未完成切换前不能贸然删除它。

## 5. 预算与双组织共存规则

### 5.1 单位、归属与应用限制

1. 预算单位按组织预算树、月份确定；不同组织可分别为 `tokens`、`usd`。
2. 同一组织内，组织、部门、个人预算单位一致；组织/部门仍是分配约束，不虚构组织级实时 S/A 共享池。
3. 团队和附加成员关系只影响既有筛选/权限，不创建新的计费 scope，不把一个人重复记入两份个人预算。
4. 个人预算当前主键为月份、scope 类型、个人标识；同一人不能因加入两个组织自然获得两种独立额度。
5. 请求按个人及适用的应用 scope 执行限制；应用是独立维度，不由组织预算覆盖。两者单位可以不同，不能相加。
6. 平台默认订阅及 system/application 类型的例外沿用 main 的实际映射，必须逐项验证，不按订阅显示名硬编码豁免。
7. “仅显示个人额度”不取消默认应用的计量或限制；共享应用若有硬限制，仍可能影响两个组织。
8. 是否拦截与预算单位分开，沿用部门 `audit/block` 及应用 `enforce` 语义，不因显示曲线改变平台策略。
9. 保持既有 UTC 月度计费边界，界面按用户时区显示；不把 Asia/Shanghai 展示时间变成新计费周期。
10. 联系邮箱、显示名、今日成员归属不回写旧月份的预算父级和历史用量。

本次目标为保留 Contoso Global 的 Token 配置，为 Test Org-USD 安装 USD 能力。
后续用户已明确组织每月 100.00 USD、Test Dept-1-USD 每月 70.00 USD，取代早期截图示例。
个人金额、模型和应用限制仍须逐项确认，不自动分配；Test Org-2-USD 默认不动。

### 5.2 金额的精度与可用性

- 使用现有 `NUMERIC(30,14)`、Decimal 和 main 的价格/结算模型，API 权威金额采用十进制字符串。
- 价格覆盖输入、输出、缓存读取、缓存写入及适用上下文阶梯，不能只导入输入/输出单价。
- 请求准入绑定不可变价格快照；后续调价不重算该请求的预留、历史费用或强行回填原始用量。
- 精确计价只要求实际非零消费分量具备价格，沿用 `025_usage_cost_component_prices`；不能把未知成本当作零。
- 保留 pending、保守上界和证据等级；超时、断线或错误码本身不证明免费或应释放全部预留。
- 新 USD scope 无历史用量可确认零期初；有历史未定价/估算用量时明确不可就绪，不能为了启动补零。
- 一个 USD scope 的未定价不能污染其他无关组织，Token 组织也不能因全局金额汇总被错误阻断。
- 组织从 Token 切 USD 沿用当前比例调整/审计算法，并明确单位切换不是把 Token 按固定汇率兑换成美元。

已有执行 scope 的单位切换复用 `BudgetRecoveryService.policies()`：先 quiesce，等待活动/保守预留和
待处理 dispatch 清空，再通过 `budget_switch_usage()` 核对旧单位确认余额并取得新单位真实期初，最后
写入对应 revision 的新策略。不能直接修改 Table 的 `budget_mode` 或仅依据数据库预算行已更新显示“网关已生效”。
API、插件和预算页应区分保存成功与策略同步完成；切换中不能把旧单位的账本数值按新单位显示。

## 6. API、能力声明与错误契约

本节为拟议契约，实施时先查现有能力端点并复用；确需新增时同步 OpenAPI 与前端类型。

### 6.1 平台预算能力

拟议 `GET /api/v1/budgets/capabilities`，使用既有会话及菜单/数据范围校验，不做推理调用。
按当前可用目标和已验证安装状态返回可用预算单位、原因代码、展示提示及是否需要客户端升级。
不能只用 `BUDGET_EXECUTION_ENABLED=true` 计算 `usd_available=true`。

USD readiness 至少包含：完整迁移、匹配包、目标注册、允许的委托来源、可信服务身份配置、
schema-two/所有可达修订覆盖、共享 fence、rollout/period/scope、价格/计数契约、账本连通性及结算能力。
只读能力接口不能每次串行扫描 ARM、全部 Table 或取得管理令牌；使用受控安装证据及健康快照，注明时间和过期状态。
过期或未知显示“待验证”，不缓存成永久就绪；真正写预算、发布和请求准入仍执行权威检查。

只向 Owner 返回安装细节，普通用户只看本人可用能力与安全提示，不暴露秘密或跨组织配置。
多目标时逐目标判定；一个目标就绪不能授权向另一个未安装目标发送 USD 请求，也不能静默退回旧计量。

### 6.2 预算写入与前端

- 未就绪时禁用 USD 选项并显示中文原因；页面加载中不提前放开。
- 保留后端 503 保护；建议补充稳定机器错误码与可读说明，不能只修改 HTTP 状态来假装修复。
- 前端能力读与保存之间发生漂移，保存应拒绝并刷新状态，不展示成功或尝试 Token 回退。
- 单位切换展示下级额度预览、可用价格与历史限制；并发保存保持数据库约束和审计。
- Token 与 USD 的跨组织总览分别汇总；不得把美元与 Token 相加成一个总预算或百分比。

### 6.3 客户端能力与用量 v2

通过既有 catalog/usage 响应扩展版本及能力信息，必要时增加只读客户端能力端点。
插件版本声明只用于展示协商，不是授权依据；没有声明视作旧契约，不把旧插件当成登录失效。

内部预算响应应区分：`budget_mode`、币种、period、confirmed、reserved、upper_bound、available、limit、
enforcement、scope/账本状态、快照时间及单调版本。字段精确名称在 OpenAPI 实施时锁定。
未配置、未初始化、价格未知、暂时不可用与确认为零是不同状态，不能统一返回空窗口或零消费。
个人设置、预算人员列表、客户端用量应复用相同账本读模型，不另写一套历史 SQL 算法。

### 6.4 版本兼容策略

- Token 旧契约字段与行为保持；USD 个人行不得再调用 `int(token_limit)`。
- v2 精确金额用字符串；转换到宿主标准 `amount/limit/used` 数值仅用于展示，不用于服务器扣费。
- 本地提前阻断基于平台明确提供的可用额度；显示“实际已用”和“预留/保守占用”时分别标注。
- 若原生卡片数值用总占用来保守提示，必须说明口径，不把占用冒充实际已结算费用。
- 明确支持的旧插件可降级展示；无法正确处理 USD 开关的版本返回可操作的升级提示，不错误注销账号。
- 先发布协议兼容代码及插件下载包，验证后再给目标组织启用 USD，避免先开预算再让旧插件报错。

## 7. 原生额度卡片、趋势及价格

### 7.1 不修改宿主的可行路径

本地客户端源码只读检查显示 `QuotaWindow.Unit` 为字符串，已有供应商使用 `USD`。
因此优先通过插件标准 usage 窗口输出 Token 或 USD，不新增宿主页面或修改宿主额度组件。
该检查不是对所有已发布客户端版本的兼容认证，必须实测目标安装版本、明暗主题和小额精度。

额度识别改用内部稳定窗口身份（用户、scope、period、单位），不再只按中文标题匹配。
对宿主只发送其已支持的字段；内部扩展字段在适配层转换，不能假设宿主支持新的预算状态协议。
只输出个人窗口，不输出应用共享额度；模型价格、个人预算和应用限制仍是三个独立概念。

### 7.2 原生趋势与开关规则

| 平台模式 | 本地选择 | 窗口 `aside` | 预期 |
| --- | --- | --- | --- |
| audit | 关闭 | true | 不声称本地硬拦截；原生历史可能不采样 |
| audit | 开启 | false | 宿主按原生机制记录并尝试本地阻断 |
| block | 不可关闭 | false | 平台强制控制优先，插件本地辅助 |

宿主当前历史采样会跳过 `aside` 窗口，因此“一个账号有曲线、另一个没有”可能是控制模式差异。
不能为画曲线伪造平台 block 状态；保留平台 block 优先及已有本地开关文件的用户绑定校验。
本次不承诺在不改宿主的前提下，把自定义开关移进原生用量页面；继续使用宿主支持的插件交互入口。

### 7.3 历史与升级

- 新版插件调整 `personalQuota()`、本地拒绝逻辑、趋势单位和金额格式，去除固定 Token 标题/模板。
- 原生曲线仍由宿主正常采样，不手写宿主 `quota-history.json`，不把平台历史强塞入原生曲线。
- 插件自己的历史增加契约版本/单位/周期分段；保留旧 Token 点，不与 USD 点连接或补造采样。
- 独立“查看额度趋势”可以保留为补充，不冒称已经嵌入原生卡片，也不替代可用的原生历史。
- 用量窗口失败、未知或 stale 时不借用上次其他单位的数据，不把不可用误判为已用尽。
- 保留用户版/订阅版独立 provider 命名、账号去重、图标、ZIP/解压目录同名和平台预生成图标接口。
- 模型价目沿用平台已有输入、输出、缓存分量及上下文阶梯导出；金额统计使用价格，不以预算上限推导价格。

## 8. APIM 兼容策略

### 8.1 显式 schema-two 升级，不整份替换客户策略

以现网父策略、操作策略、共享/服务策略、依赖的片段及精确 ETag 为输入，识别已知版本。
在离线计划中逐项说明：客户端入口、员工入口、订阅入口、TPM、模型映射、路由、事件、缓存指标、
Observer 头和预算写入的前后差异。未知版本、歧义、客户自定义分支或缺少读回证据必须停止。

不能只删除 `clientContextPolicyVersion` 标记、删掉一处 `hasEmployeeToken` 或放宽全局校验器来过编译。
若需要识别旧插件策略，增加版本化且完整验证的匹配/转换器；只接受实际证明的旧结构和摘要。
新策略中使用 main 原生委托入口，不再次调用旧插件组合器复制员工账本逻辑。
所有后续模型发布和控制平面生成的父策略必须识别同一新契约，不能发布后再把旧插件补丁手工贴回去。

### 8.2 保留修订与候选修订

- 新建受保护候选修订，不直接覆盖当前生效父策略；创建后即按官方协议封锁普通流量。
- 非当前修订也可能通过 revision URL 被访问，不能把“不 promote”等同于安全隔离。
- 共享 fence 必须覆盖目标 API 的所有可达修订与 Gateway，并验证 `<base/>` 继承及执行顺序。
- 保留修订不能成为旧准入旁路；保留但 fenced，不删除以隐藏差异。
- 在 `prepared/paused` 下，只允许主协议支持的精确验证修订、个人、应用和订阅组合进入。
- 不影响其他不在安装清单中的 API；如果修改服务层策略，明确 API 白名单并证明其余 API 不受影响。
- 更新已有资源使用具体 `If-Match`，新资源使用明确的不存在条件；拒绝 `*` 和无条件覆盖。
- 保留操作定义、模型别名、后端/池、身份验证、限流及原路由，不能用重建订阅来“修复”兼容。

读回须核对响应格式、版本和内容。Azure 可能返回 BOM、CRLF 或不同 XML 序列化，明确记录允许的
表示层规范化后再比较；不得通过删除鉴权节点、改变表达式或忽略字段来掩盖实际策略漂移。

### 8.3 Observer、事件与金融证据

API、Telemetry、Control-plane 和 Observer 必须具备匹配的事件/完成协议，不能只比较三个应用的 Core digest。
逐次关联 request ID、APIM correlation、目标/Gateway/修订、receipt、正式事件、数据库任务和 S/A/D 记录。
保留 main 对正式证据、完成确认、诊断恢复的等级与不可变性处理。
流式连接、缓存、错误及中断必须沿用未核实费用的保守保留；不能在 SSE 结束前预判免费。
Observer 如需更新，使用现有四个运行文件及三个共享完成模块的构建白名单，保留旧镜像精确 digest。
不把整个工作树打入镜像，不为测试另建未经批准的长期计费资源。

计数契约绑定实际发布模型、协议、路由和已经验证的输入/输出边界及功能集合。
原生计数的 estimate 不能通过随意加 padding 冒充 verified upper bound；不支持的远端状态、
服务端工具、后台执行、图像或思考参数必须按 main 的契约显式处理，不能删字段或换模型取得一次 200。
拒绝请求的零消费证据使用已验证且精确匹配的规则，不能把所有 4xx/5xx 都当成免费终止。

## 9. 迁移与初始化脚本

### 9.1 SQL 结论

当前 40 个迁移已覆盖本轮已识别的结构需求，没有证据表明修复 503 要重写或重跑旧 SQL。
关键链包含 `010_budget_execution_protocol`、`017_budget_terminal_observation`、
`018_budget_reservation_resolution`、`021_usd_budget_reservations`、
`023_usd_reservation_resolution`、`025_usage_cost_component_prices`；不能只挑这六个替代完整链。
重复数字前缀不合并、不重命名；版本继续使用完整文件名去掉 `.up.sql`。

统一身份、后端委托缓存、客户端金额窗口与只读 readiness 优先复用现有结构，不预设新增业务表。
实现时如确需增加持久审计或修正数据库函数，追加新的完整编号迁移并测试旧包兼容，不能修改已应用文件。

### 9.2 bootstrap 与常规发布

- 保留 `backend.migrate -> backend.bootstrap -> API` 的启动失败阻断和 Owner 幂等行为。
- 不在普通启动中自动插入 active rollout、seed 余额、启用执行开关或覆盖客户策略。
- 为现有网关补注册元数据时精确复用已有 profile、凭据和资源身份，不生成第二个默认网关。
- 新装也默认关闭执行协议；只有明确的安装清单可以启动初始化。
- 现有 `bootstrap_storage_route` 对首次创建 rollout 要求无历史用量，不能用于强行接管当前有历史数据的环境。
- API 包含全部迁移和所需协议文件；三应用包、函数实际索引与业务运行均需验证。

### 9.3 新增受控安装工具（拟议）

建议新增 `scripts/install_budget_execution.py`，复用已有编译器、账本服务和受控修订/读回机制。
保留 `prepare_budget_execution.py` 的离线、默认关闭语义，不把其改成执行即激活的快捷脚本。

| 阶段 | 工具职责 | 允许的变更 |
| --- | --- | --- |
| plan | 只读盘点、比较、计算摘要及阻断原因 | 本地计划文件，无云写入、无推理 |
| prepare | 已审核清单下创建 fenced 候选、安装前置组件 | 仅列明的候选/片段和必要准备，不接普通流量 |
| initialize | 暂停准入并排空后，核对并建立期初和 scope | 必须处于已验证共享 paused fence 内 |
| verify | 指定隔离个人/应用/订阅/模型的正反例和链路对账 | 明确有次数/费用上限的小额推理与临时测试配置 |
| activate | 对所有验证通过的读写方及 fence 有序激活 | 精确目标，逐步读回，不盲目一起打开全部开关 |
| recover | 根据 journal 和实际外部状态恢复或停止 | 不自动重放未知付费请求，不自动回退金融状态 |

上述是拟议操作阶段，不是现成 CLI 命令。安装器应从已有 main 契约派生参数和状态，避免复制一套协议。
计划必须绑定源码/包摘要、资源/API/Gateway/修订、策略摘要与 ETag、scope/period、epoch、
委托白名单、价格/计数契约、备份证明、验证范围、性能门槛及允许的资源写入清单。
不在配置文件保存 Key 明文；参数只引用受保护凭据来源。未知字段、目标漂移、过期计划必须拒绝。
写入前持久化 intent，记录结果和读回；journal 独占创建、0600，允许可验证的 no-op，不允许删除 journal 重试。

### 9.4 初始化状态的特殊顺序

main 的 `BudgetScopeService.prepare()` 依赖数据库 active rollout 和 `scope_sync_enabled`，
不能假称现有实现能够在数据库完全 prepared 状态直接完成 scope 初始化。
正确安装流程要区分“数据库协调状态 active”与“网关允许普通准入 active”：

1. 先确认所有可达旧准入已被共享 `paused` fence 阻断，排空在途流量及遥测。
2. 在受保护维护状态中建立已核对的 rollout 和初始化所需协调状态，再调用 main 的 seed/policy 服务。
3. 即使数据库/部分 scope 已标 active，普通请求仍被网关 paused fence 阻断，只允许协议定义的验证范围。
4. 匹配读写包、scope、Table、价格及真实验证全部通过后，才把网关准入切为 active。

每个作用域的期初只建立一次。沿用现有期间/人员来源，核对数据库目录投影；不得从过时静态示例补造业务人员。
按 `CutoverReadback` 的现有要求验证 fresh readback；当前上限为 30 秒，不能拿几分钟前的快照授权初始化。
存在旧在途/上界或新旧余额不一致就停止。保守费用如需处置必须有批准和不可变证据，不允许清表。

## 10. 性能与可用性设计

### 10.1 预期新增开销

| 环节 | main/当前实现特征 | 本轮要求 |
| --- | --- | --- |
| 登录与目录归一化 | 已有统一会话与治理人员标识 | 不新增模型调用前的 Graph/SSO 网络查询 |
| 委托状态 | 请求路径查询 active rollout 和目标配置 | 复用一致读结果，能力展示不重复全量云预检 |
| 托管身份令牌 | main 每次新建 provider，缓存仅存实例内 | 生命周期级复用，按身份与 audience 隔离、到期刷新、并发合并 |
| HTTP | 用户代理每次创建并关闭 AsyncClient | 应用生命周期连接池，凭据/身份头仍逐请求设置 |
| 财务准入 | scope 摘要读、ETag 条件批写、dispatch 协调及 fence | 保留强约束，不靠缓存余额省略原子检查 |
| USD | 读取价格投影，按契约可能调用原生计数 | 避免一次请求内重复取相同价格，不能丢失不可变快照 |
| 完成与对账 | 非流式可能在 APIM 完成路径读写；流式依赖完成证据/恢复 | 分别测首包、结束和结算滞后，不只看总响应时间 |

本地 Mock 验证：两次新建 `ManagedIdentityTokenProvider` 产生两次身份端点请求；复用实例为一次。
这不是线上延迟基准，也不是两次直接访问 Entra。provider 已有到期/身份变化失效及并发锁，优先复用而非另造缓存。

### 10.2 缓存与连接池的边界

- 缓存的是服务器身份令牌，不是把个人登录/grant 的撤销检查缓存掉。
- 沿用 main 的临近过期保护；实例身份、endpoint/header、audience 变化必须失效。
- 权限、人员禁用、账号绑定、模型发布及订阅访问按当前权威路径检查；任何缓存须绑定既有 revision。
- 额度展示可使用短时快照，财务准入不能直接相信展示缓存；未知或 stale 不冒充实时余额。
- 连接池不设置跨用户共享的默认 Authorization/订阅头；保留目标域名约束、超时、禁重定向和错误清理。
- SSE 断开时及时关闭相应 response，不能把一个客户端断线传播成其他请求的连接池关闭。
- 已激活 grant 的重复加锁可单独优化，但不能删除 generation、撤销及替换授权的并发保护。

### 10.3 性能验收

先记录当前链路及 main 通用委托链路的可比基线，再测兼容适配器；不把模型自身波动算成鉴权计算耗时。
记录登录/grant/目录/模型查询、令牌 cache hit/miss、APIM admission、Table 操作/冲突、首包、总耗时和结算滞后。
覆盖并发 1/5/20、同人/多人、Token/USD、一个/两个 scope、冷/热启动、流式/非流式、断线与依赖故障。
输出 p50/p95/p99、吞吐、连接数、数据库锁等待、429/503 和错误率；不给未经压测的固定毫秒承诺。
先用隔离存储和可控上游测并发，再按批准次数/费用做少量真实验收，不用生产模型做无上限压测。
具体性能上限及允许退化值须写入执行清单；缺少基线/门槛就不标记性能验收通过。

## 11. 生产前备份与恢复校验

现有备份证明“文件已捕获、可解密，数据库实际还原”，不证明在线快照之间已完成停流对账。
开发与测试期间仍会有正常调用，正式切换必须刷新快照并再次校验，不能无限期沿用 2026-10-16 的结果。

必备备份范围：

- 数据库 custom dump、迁移版本/校验和/应用时间、账号/目录/预算/权限/模型与历史记录摘要。
- APIM 全部相关修订、父/操作/共享策略与片段、API/操作定义、当前 release、ETag、后端/池及秘密引用。
- 订阅元数据和原始 Key、Named Value 的必要秘密值；只读导出，不轮换密钥。
- 原子与旧账本、预留、控制 fence、价格投影和必要处理检查点；明确每份快照的时间与读取范围。
- API、两组 Functions 精确运行包与设置，Observer 镜像 digest/设置，原部署参数和现有身份权限配置。

加密备份与密钥分开保存，核对加密/解密摘要；在私有 PostgreSQL 实际还原，不以 `pg_restore --list` 替代。
验证新/旧代码对候选数据库的读取兼容；APIM 备份解密和结构检查不冒称实际云回滚演练。
临时备份权限只在精确范围授只读权限，journal 记录，结束撤销并验证不存在；不得提升运行时 Publisher 权限。
恢复材料离开 `/tmp` 保存到受限持久目录；备份失败、未验证或缺关键状态，禁止任何 APIM 写入。

- 安装器先具备只读 plan；全部本地回归及隔离真实数据库验证通过后再构建运行包。

### P2：备份、依赖与候选准备

- 刷新并验证第 11 节备份；确认临时恢复材料可取得且密钥可用。
- 只在必要时按精确计划补目标注册、身份权限、Table 网络可达性及 Observer 升级，不重建平台。
- SQL 如有新增，先使用现有迁移入口一次应用并验证，再启动依赖新结构的包；当前已有 40 项不重写。
- 部署匹配 API/Telemetry/Control-plane/Observer，财务准入保持关闭；验证原 Token 业务未回归。
- 审核并创建严格 fenced 候选；校验所有后续写入的 ETag 与资源范围。

### P3：维护暂停、排空与初始化

- 暂停配置/模型发布写入和相关后台任务，确认无未完成发布、未知 ARM 写入或租约持有者。
- 安装并逐修订验证共享暂停 fence，停止旧准入，而不是仅隐藏页面或停止平台 API。
- 等待 APIM 在途、Observer、Event Hub、遥测及结算工作排空；核对所有必要检查点与旧余额。
- 比较逐个人/应用的 confirmed、pending、upper-bound；不把 R 行为 0 当成唯一条件。
- 在共享 paused fence 内、满足正常预算写入保护后，通过平台预算 API 配置批准的 USD 组织、部门、个人及 block。
- 优先按最终预算单位创建种子；若 scope 已按 Token 初始化，走第 5.2 节的 quiesce/余额核对/单位切换流程。
- 使用 fresh readback 建立同一 epoch 下的 scope 及期初，按第 9.4 节保持网关暂停与协调状态分离。
- 未就绪的 scope 必须可见地失败；不能让初始化“部分成功”授权整个目标正式接流量。

### P4：隔离真实验证

- 使用明确批准的测试个人、应用、订阅与已授权模型；不移动日常用户、不复用其已有 Agent 会话。
- 验证一个 Token 人员和一个 USD 人员的实际调用、receipt、价格、预留和最终结算。
- 覆盖正确身份、伪造用户、错误 audience/服务身份、无效订阅、越权模型、额度用尽与依赖故障。
- 覆盖流式工具调用和原生协议；验证请求/会话/Agent 归因与费用仍可关联。
- 使用真实网关和真实订阅头，关闭测试重试；超时或结果未知不自动重放。最低输出配置遵循已验证协议。
- 完成临时测试配置、会话/令牌及权限的清理核对；保留已发生的真实用量及审计，不删除痕迹。

### P5：激活、双组织验收与观察

- 仅在所有 gate 通过后激活相关读写任务与共享 fence，逐项读回，不用“一次改完所有环境变量”代替状态机。
- 核对维护期配置的目标 USD 组织、部门、个人和 block 已在数据库/Table 生效，金额和名单与批准清单一致。
- Token 组织原值和历史摘要保持不变；现有其他组织及订阅版行为不变；共享应用影响单独验证。
- 验证预算页、人员列表、个人设置、插件额度卡片/本地开关/原生趋势、模型价格与请求费用一致。
- 观察正式结算任务、未知/冲突证据、账本版本、错误率和性能，时间窗口覆盖正常遥测与恢复周期。
- 恢复原后台运行状态，撤销临时授权，发布说明只列实际通过项，所有剩余 gate 明示。

维护计划避开现有约 00:10 的数据库关停窗口，执行前以真实策略为准。
如依赖被外部策略停止，停止切换并按既有授权恢复，不通过改治理策略解决；发布后不主动关闭数据库。

## 13. 回滚与故障处置

| 所在阶段 | 允许的处置 | 禁止做法 |
| --- | --- | --- |
| 未接收新协议请求 | 根据 journal 恢复候选/已审查策略和配置，读回原路径，保留加法式迁移 | 覆盖全库或删除新表来“恢复干净” |
| scope 已初始化但仍 paused | 维持 fence，核对实际是否发生验证消费，按证据恢复；未用种子保留审计 | 删除 seed、重用不同 epoch 或先解封旧准入 |
| 已有新协议消费 | 先暂停准入并排空；优先修复/前向恢复，保留金融兼容的读写包 | 只关闭开关、直接恢复旧父策略或旧余额 |
| 需要返回旧准入 | 单独审核余额转换和未结预留处置，形成新鲜且一致的证据后转换 | APIM 已回旧策略但数据库/Table 仍处于新执行 epoch |
| 外部写入结果未知 | 记录 unresolved，读取实际资源与请求证据后制定恢复动作 | 重试未知推理或新建 journal 绕过停机保护 |

回退包必须能读取已经发生的新财务数据；本轮金额协议激活后的回退，不能套用上次“仅包更新”的兼容证明。
Table 余额、数据库、Event Hub 检查点不可独立恢复到不同时间并继续服务；灾难还原需单独协调重放与幂等核对。
历史策略保留是证据和恢复材料，不是随时可以绕开 fence 的紧急旁路。

## 14. 测试与验收矩阵

| 类别 | 必测内容 | 通过条件 |
| --- | --- | --- |
| 登录与人员 | 密码/SSO、禁用账号、人员归档、显式绑定与未绑定、改显示名 | 复用统一身份；撤销及时生效；不重复开户 |

| 模型权限 | 角色/个人/应用/发布状态与撤销 | 在既有边界内拒绝，未发送付费请求 |
| 可信委托 | 错 tenant/audience/client/oid、伪造个人、冲突头、未授权地址 | 失败关闭，不信任 Agent 自报身份 |
| 原生协议 | Responses、Chat、Messages、适用图像、流式工具/思考/取消/错误 | 不因复用控制台 DTO 丢字段或破坏流 |
| 策略组合 | 真实现网样本、旧插件分支、目录/TPM 扩展、嵌套验证器、未知自定义片段 | 严格识别；未知拒绝；新旧编译器后续发布一致 |
| 修订与 Gateway | 当前、所有旧 revision URL、候选、所有实际承载节点 | 无旧准入绕过 fence；验证入口范围精确 |
| 双组织 | Token/USD 并存、单位继承、切换比例、应用独立限制 | Token 原值不变，USD 实际按金额控制 |
| 财务精度 | 小额、缓存读写、零分量缺价、上下文阶梯、调价 | Decimal 一致，快照不可变，无价格不造零 |
| 并发 | 同人同应用、跨应用、边界额度、条件写冲突 | 不超发、不重复扣、失败保守且可恢复 |
| 未知结果 | 超时、网络中断、SSE 断开、依赖 5xx、重复/乱序证据 | 无自动免费、无不明推理重放、证据审计保留 |
| 初始化 | fresh DB、原 20 项升级至 40 项、完整候选增量、重复执行、错误校验和 | 数据与迁移身份保留；无自动激活 |
| 期初 | 有历史/无历史、未定价、旧预留、过期读回、部分成功 | 每 scope 只 seed 一次；不清零；不整体误报通过 |
| 金额接口 | 合法 USD token_limit=NULL、无预算、未初始化、缺价、stale | 不再 int(None)，状态和金额准确 |
| 插件显示 | 旧/新版本、USD/Token、明暗主题、小额、账号改名与 ZIP 安装 | 原生卡片正确，不重复账号、不修改宿主 |
| 曲线/开关 | audit、用户开关、平台强制、单位/月切换、已有历史 | 不伪造 block，历史分段，平台强制不可关闭 |
| 价格与用量 | 平台导出/刷新、模型/Agent/会话关联、缓存费用 | 平台与插件可解释，不借应用额度掩盖个人问题 |
| 运维 | 备份解密、实际还原、ETag 漂移、角色撤销、函数索引和任务执行 | 证据完整；HTTP 200 之外有业务证明 |
| 性能 | 冷热身份、连接池、同人/多人并发、财务路径与结算滞后 | 达到事先冻结的基线门槛，无鉴权/财务降级 |
| 回滚 | 未准入、验证已消费、正式激活后、未知外部写入 | 按阶段验证，不允许余额倒退或旧 revision 旁路 |

先完成单元/契约/前端与插件 Node/Bun、APIM 表达式 .NET、隔离 PostgreSQL、打包/Core/Observer 检查，
再进行候选真实 APIM 测试。缺失运行时或数据库工具的 skipped 不能计作验收通过。
客户端浏览器/原生卡片的实际验证与服务端 API 验证分开记录，模拟认证状态不等于真实登录验收。

## 16. 其他已知部署缺口与本轮边界

[初始化升级审计](initialization-upgrade-audit.md) 中两项通用缺口在本方案编写时仍需单独处理；
是否已在后续代码修复需重新核对，不能从历史审计推断：

1. 新平台复用已有 APIM 时，平台 VNet 创建条件仍与新建 APIM 绑定。应分离平台网络和 APIM 创建条件，
   对复用网络给出明确前置要求；不能接管或重写客户未知网络。
2. 动态应用 TPM 规划 helper 尚未接入公共升级命令。应接入现有修订、预览、维护、读回与回退引擎，
   不能要求重发模型才能获得兼容升级。

这两项不是当前 USD 503 的直接原因，也不能顺带通过整个平台重部署来解决。
若本轮交付宣称“完整支持公共新装/升级”，它们必须作为独立工作项验收；
若仅安装当前既有环境，则明确范围并证明不触发这些路径，不能将其标记为已修复。

## 17. 发布放行条件

以下全部完成才允许宣称本轮“配置、测试、上线完成”：

- [ ] 自定义组织及密码登录不依赖 Entra 用户同步，已有登录与绑定行为未回归。
- [ ] 真实默认订阅和服务器密钥持有边界不变，全部允许来源通过可信鉴权。
- [ ] 原生流式/工具及既有 Agent 协议通过，新旧策略组合缺口已修复。
- [ ] 完整迁移、四方运行时、目标、权限、网络、计数与价格契约验证通过。
- [ ] 旧修订全部受 fence 约束，期初正确，验证与普通准入严格隔离。
- [ ] Token 与 USD 组织真实调用、预留、结算、拦截均通过；共享应用限制无误放行或意外豁免。
- [ ] USD 个人额度、模型价格、费用、趋势和本地开关通过，无异常、假零或单位混算。
- [ ] 正式切换前新备份/还原校验完成，journal 和按金融阶段划分的恢复路径可用。
- [ ] 性能及故障门槛通过，临时账号/授权/权限清理验证完成。
- [ ] 实施与发布记录清楚区分本地、模拟、候选、真实线上结果，没有未披露的失败或 skipped。
