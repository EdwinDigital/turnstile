# AIGateway-Proxy 客户端需求分析

初版日期：2026-10-11；需求扩展：2026-10-12。范围：Turnstile 用户菜单、下载页面和 magpie 供应商插件；不修改 magpie 源码，不发布到公共 npm。

状态：下文「V1 已交付基线」保留指定订阅插件的历史边界；「V2 用户登录版」为待开发需求。详细方案见 [用户登录版设计](user-mode-design.md)，实施和验收状态见 [实施记录](implementation.md)。本轮仅更新文档，不代表 V2 已实现或上线。

## V1 已交付基线

## 用户流程

1. 登录用户在头像菜单选择「下载客户端」，进入独立页面；两个数据源下均可访问，下载数据始终来自平台 APIM。
2. 选择有权限的应用订阅、对应平台网关及主/备用订阅密钥；页面展示网关地址、模型及下载包含密钥的警告，不显示密钥。
3. 下载 ZIP，内含完整供应商插件、当前订阅配置和安装说明。解压后在 magpie「插件」页添加本地文件夹，首次加载自动导入配置；自动导入失败时点击「导入配置」。
4. 供应商及订阅获授权的已发布对话模型出现在 magpie 中，可供其他 Agent 通过 magpie 网关使用。

## 当前核心验证边界（用户 2026-10-11 更新）

- 用户明确要求先不考虑权限控制，先实现核心功能验证。第一阶段暂不开发 Member 应用行归属、部门/团队委派或新的权限菜单；API 沿用现有 OwnerSession，不开放匿名或普通用户密钥导出。
- 保留现有系统订阅排除、启用状态、网关一致性、模型策略和跨站保护。这些是配置正确性及既有系统约束，不修改既有授权/预算/网关策略。
- 下载导出已有订阅密钥，不创建或轮换密钥。响应 no-store，私密配置不写 Git、URL 或日志。网关只接受当前平台 APIM 的配置，不接受浏览器任意 URL。
- 普通用户下载和精细权限控制延后，核心交付不宣称已经支持。菜单可见，非 Owner 页面明确提示当前阶段限制。

## 协议和范围

- 使用 OpenCode v1 兼容供应商插件，不用无 fetch 能力的网关中间件。依照官方文档及本地 host.js 核对入口和钩子。
- 根据生效网关发布的 api_format，为模型选择 Responses、Messages 或 Chat Completions；使用平台模型别名，不用 Foundry 上游部署 ID。
- 首期只导出已启用、已发布、应用允许访问的对话模型；图像生成不伪装成对话模型。动态发现仅保留下载快照与线上 /v1/models 的交集；新增授权模型需重新下载。
- 一个下载包对应一个应用订阅和网关，稳定且隔离的供应商 ID 允许多个订阅并存；不覆写已有供应商登录。
- 不修改数据库 schema、APIM 策略、预算控制、模型授权或平台基础设施。

## 验收

- Owner 用户菜单入口、桌面/手机布局、表单联动、空列表、错误/重试、重复提交及会话过期。
- API 401、越权 404、系统/失效订阅、错配网关、跨站 POST、无已发布模型、密钥读取失败及敏感响应缓存。
- ZIP 内容完整、无代码/路径注入、配置与所选订阅一致；插件不向其他地址转发密钥、不跟随重定向，取消和流式响应保持原样。
- 隔离 HOME 导入真实 magpie；使用指定 cc-switch 订阅执行真实模型连通和流式调用。保留用户原有登录、插件和 Agent 配置。
- 发布前保留当前生产包，构建并验证完整 API 包；上线后核对真实页面、授权下载、magpie 导入和调用。测试与发布证据写 implementation.md，私密配置和截图保留 Git 外。

## V2 用户登录版（2026-10-12）

本节替代新用户版中「仅 Owner 导出密钥、只导出对话模型、下载快照、没有外部登录、不新增服务端能力」等旧限制；不追溯改变 V1 行为。此前「先不考虑精细权限控制」是 V1 验证边界，不能据此让新用户版读取所有人的订阅、模型或额度。

### R1 两种下载方式并存

- 下载客户端页面同时提供「指定订阅下载」和「指定用户下载」，分别标明适用场景、版本、凭据风险和安装步骤。
- 两版对外名称分别为「AIGateway-Proxy 订阅版」和「AIGateway-Proxy 用户版」。旧版保留已安装的技术名称 `aigateway-proxy`，新版使用 `aigateway-proxy-user`；package.name、供应商 ID、根目录、ZIP 文件名和本地状态命名空间都必须隔离，不能仅依靠显示名或版本号区分。
- 指定订阅版冻结当前 0.1.1 的包结构、认证方式、供应商 ID 和下载接口；继续选择应用订阅、网关和主/备用 Key，保留「导入配置」「更新API Key」。旧版不自动升级或迁移到用户版。
- 指定用户版为独立插件包，建议初版 0.2.0。下载当前登录用户的引导包，包含平台地址、公开客户端标识和非秘密用户绑定信息；不包含密码、浏览器 Cookie、APIM Key、Access Token 或 Refresh Token。
- 个人包默认绑定下载者；重新登录可更新同一用户的会话，不自动改为另一个用户。换用户使用该用户自己的下载包，不提供普通用户代他人下载能力。

### R2 平台登录与重新登录

- 未登录时，从 magpie 插件/供应商的现有登录入口打开平台验证页面，使用平台已有登录方式认证，显示申请设备、用户和授权范围并显式确认。
- 使用类似 OAuth 的设备授权流程；完成后 magpie 显示真实平台用户登录状态。新用户版不采用 V1 的「本地回调导入包内 Key」冒充平台认证，不提供「更新API Key」。
- 供应商认证方法提供「登录平台」「导入模型配置」「重新登录」；登录后可以继续导入，重新登录强制重新验证身份并刷新订阅目录。
- 点击导入后打开平台订阅选择页；页面实时读取当前用户可访问的订阅，而非预置截图中的 cc-switch 或下载时快照。原生 magpie 动态下拉可作为兼容性验证后的增强，不作为不修改宿主即可实现的既定事实。
- 登录/导入取消、超时、拒绝或失败不得破坏已有有效配置；注销、用户禁用、权限撤销后不得由自动导入或缓存恢复登录。

### R3 平台订阅与模型目录

- 首期一次导入选择一个应用订阅及其关联网关；同一订阅的多个可用网关只能从平台返回的合法关联中选择，不能手填 URL。后续多选是独立扩展，不默认叠加历史订阅。
- 目录与调用均由平台判断用户、应用、订阅、网关、人员模型策略和生效发布；空授权清单不得回退为所有模型。组织成员关系或菜单可见不自动等于拥有应用调用权。
- 导入内容包含文本模型和文生图模型的公开 ID、上游映射、协议、能力、已知限制及目录版本。新增模型发布并授权后可动态刷新，不要求重新下载插件。
- 每次导入完整替换当前用户版插件拥有的有效选择与生成模型集合，移除其旧订阅、旧模型和旧派生配置，不累积账号槽位。保留其他供应商、V1 插件和 Agent 的非本插件配置。
- 「覆盖导入历史」指覆盖本机当前有效配置，不删除平台安全审计、调用原始记录、预算账本或其他供应商历史；不能重写历史调用归因。
- 模型别名映射由平台注册元数据自动生成，验证响应确为预期上游后才适配返回名；真实模型替换仍可诊断，不硬编码 Foundry 后缀。

### R4 文生图

- 明确区分图片输入（视觉识别）与图片输出（生成）；支持平台已发布的 OpenAI Images 文生图协议，不把图片模型伪装成对话模型。
- 图片请求仍通过当前用户身份、所选订阅和已发布网关的授权/预算链路；用户版不向 Agent 下发 APIM Key。
- 已发现 magpie 当前通用插件的原生图片选择器限制。实现前必须做兼容性验证；必要时使用插件配套的受控图片 API 桥接或 MCP 工具，不修改 magpie 源码。
- 图像生成以真实图片可查看、身份/用量正确、卸载可清理为验收，不以目录里出现图片名称代替。图片编辑、视频和语音不属于本轮必选范围。

### R5 用户额度

- 用户版实现 magpie 的 `auth.usage`，显示本人额度；所选应用的共享额度可单独展示并明确标注，不能把共享应用总额称为个人余额。
- 返回平台定义的周期、已用/可用、待结算预留、阻断模式、更新时间及数据新鲜度；未配置额度不伪造为 0 或无限。
- 复用现有预算口径和账本，不用本机 Token 累加代替跨设备汇总，不把不同层级预算相加，不把图片数量或美元直接加进 Token。
- audit 窗口仅展示，不能诱使 magpie 自行停止调用；平台后台 admission/预留/结算不依赖额度卡片刷新。
- 额度读数允许缓存并显示更新时间；缓存失效不冒充实时数据，也不能覆盖服务端实时授权判断。

### R6 验收补充

- 双版本同时安装且插件列表可区分，不触发同 provider 的 serving/prefer 冲突；导入、退出、停用、移除和升级互不影响。普通用户自助包下载、不同身份目录隔离、平台验证/授权取消和超时、同用户重新登录、跨用户个人包拒绝、Refresh Token 轮换与撤销。
- A 订阅导入后切 B，旧模型不残留、旧授权不可再调用；两次并发导入不会产生混合目录，失败保留 A，其他供应商配置 hash 不变。
- 授权新增、撤销、模型发布更新、版本化 ETag、断网/恢复、空清单和过期缓存；真实别名误报消除但不隐藏非预期返回模型。
- WorkBuddy 经 magpie 的真实文本、流式、取消、工具调用；图片生成及额度卡片分别验收，用户归因正确且不改变历史 unattributed 记录。
- 服务端权限校验、请求限速、凭据脱敏、仅允许平台域名、无开放重定向、无跨账号泄露、短缓存/并发合并、有限重试及数据库负载测试。
- 验收时记录实际 magpie 版本及界面能力；宿主不可控的按钮文案/位置、图片选择器和缓存刷新限制必须披露，不以改 magpie 源码补齐。
